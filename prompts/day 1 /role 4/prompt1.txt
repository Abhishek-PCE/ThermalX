1. YOUR MISSION
==================================================

Your task is to implement ONLY the Day 1 responsibilities of Role 4.

Role 4 is responsible for creating the data-processing layer that converts raw NASA FIRMS hotspot data into clean, validated, structured data that can be consumed by the rest of the ThermalX frontend.

The basic data flow is:

NASA FIRMS / Raw Hotspot Data
        ↓
Role 4 Data Processing
        ↓
Clean & Validated Hotspot Objects
        ↓
Map / Dashboard / Analysis / Classification

The goal for Day 1 is NOT to build the complete ThermalX system.

Build a clean foundation that other team members can use later.

==================================================
3. DAY 1 ROLE 4 RESPONSIBILITIES
==================================================

Implement the following:

A. Create a standardized hotspot data structure.

Each processed hotspot should follow this structure:

{
    id,
    latitude,
    longitude,
    brightness,
    frp,
    confidence,
    date,
    satellite
}

You may add a small number of useful fields ONLY if they are necessary for processing, but do not unnecessarily expand the schema.

--------------------------------------------------

B. Create a dedicated processing file.

Prefer:

js/processing.js

This file should contain the main Role 4 data-processing logic.

If the existing project has a different folder structure, inspect the repository first and follow the existing architecture rather than unnecessarily restructuring the entire project.

--------------------------------------------------

C. Create a processing function.

Create a clear reusable function such as:

processHotspots(rawHotspots)

It should:

1. Accept raw hotspot records.
2. Normalize the data.
3. Convert numeric values into actual JavaScript numbers where appropriate.
4. Validate required fields.
5. Remove invalid records.
6. Remove obvious prototype duplicates.
7. Return a clean array of hotspot objects.

Example conceptual flow:

raw data
   ↓
check record
   ↓
normalize values
   ↓
validate values
   ↓
remove invalid records
   ↓
remove duplicates
   ↓
clean hotspot array

--------------------------------------------------

D. VALIDATION

Validate important fields.

Latitude:

- Must exist.
- Must be numeric.
- Must be between -90 and 90.

Longitude:

- Must exist.
- Must be numeric.
- Must be between -180 and 180.

Brightness:

- Should be numeric when present.

FRP:

- Should be numeric when present.

Confidence:

- Preserve the original FIRMS confidence representation if possible.
- Do not invent confidence values.

Date:

- Preserve a usable date representation.
- Do not silently create fake dates.

Satellite:

- Preserve the satellite/platform information when available.

Do NOT destroy otherwise useful records simply because an optional field is missing.

Required fields should be clearly distinguished from optional fields.

==================================================
4. DUPLICATE HANDLING
==================================================

Implement a simple Day 1 duplicate-detection strategy.

For the prototype, use a key based on:

rounded latitude + rounded longitude + date

For example:

latitude + longitude + date

can be normalized into something similar to:

"23.4567_87.1234_2026-09-15"

Use an appropriate rounding precision.

The objective is only to prevent obvious duplicate records.

Do NOT attempt advanced spatial clustering on Day 1.

Do NOT use Turf.js yet unless the existing project already requires it.
