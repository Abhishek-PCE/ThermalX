# 6. SPATIAL CLUSTERING

Implement spatial clustering of nearby FIRMS detections.

The purpose is:

> Multiple nearby satellite detections should be treated as one possible thermal event rather than hundreds of unrelated points.

Use **Turf.js** for geographic/spatial calculations where appropriate.

Do NOT use simple latitude/longitude subtraction when Turf.js can perform the geographic calculation correctly.

Consider:

* latitude
* longitude
* geographic distance
* proximity between detections

The clustering logic must be deterministic and understandable.

Do not introduce a complicated machine-learning clustering algorithm.

---

# 7. TEMPORAL GROUPING

After identifying spatially related detections, group detections across time.

The system should be able to determine whether a hotspot keeps appearing around the same location across multiple days.

For each thermal event calculate:

### Detection Count

Number of hotspot detections belonging to the event.

Example:

```text
8 detections
```

### Unique Days

Number of different calendar dates on which the event was detected.

Example:

```text
Detected on:
September 10
September 11
September 12
September 13
September 14

Unique days = 5
```

Do NOT count multiple detections on the same date as multiple unique days.

---

# 8. FIRST AND LAST DETECTION

For every thermal event calculate:

```text
firstDetection
lastDetection
```

Example:

```text
First detection: 2026-09-10
Last detection: 2026-09-14
```

Use actual detection dates from the dataset.

Do not use today's date unless it is actually the last detection date.

Handle invalid/missing dates safely.

---

# 9. ANALYSED DAYS

Determine the number of days covered by the historical dataset being analysed.

Use this value when calculating persistence.

The roadmap defines:

> Persistence = days detected / days analysed

Implement this exactly as the MVP definition.

---

# 10. PERSISTENCE SCORE

Calculate:

```text
persistenceScore =
(uniqueDays / analysedDays) × 100
```

Make sure:

* result cannot exceed 100
* result cannot be negative
* division by zero is handled
* missing dates do not crash the application

Round the displayed value appropriately.

For example:

```text
0–20%      → Low
21–50%     → Moderate
51–80%     → High
81–100%    → Very High
```

IMPORTANT:

These thresholds are **prototype rules, not scientific ground truth**.

Do not describe them as scientifically validated.

---

# 11. RECURRENCE RATE

Create a recurrence-rate value that clearly represents how repeatedly the thermal event appears over the analysed period.

Keep the calculation consistent with the persistence logic.

Do not create a misleading metric that contradicts the roadmap.

If persistence and recurrence rate are effectively the same metric in the current MVP, structure the code clearly so that this can later be improved without rewriting the entire processing system.
