6. COORDINATE VALIDATION
============================================================

Validate latitude and longitude carefully.

Latitude must be:

>= -90
AND
<= 90

Longitude must be:

>= -180
AND
<= 180

Reject records when:

- latitude is missing
- longitude is missing
- latitude is null
- longitude is null
- latitude is undefined
- longitude is undefined
- latitude is not numeric
- longitude is not numeric
- latitude is outside valid range
- longitude is outside valid range
- coordinates are clearly malformed

Example:

latitude = 23.8103
longitude = 90.4125

VALID

Example:

latitude = 150
longitude = 80

INVALID

Example:

latitude = "abc"
longitude = 80

INVALID

Example:

latitude = null
longitude = 80

INVALID

IMPORTANT:

NASA/API values may sometimes arrive as strings.

Therefore, safely convert numeric strings to numbers where appropriate.

Do not reject a valid numeric string simply because its JavaScript type is string.

For example:

"23.8103"

may become:

23.8103

9. CONFIDENCE CLEANING
============================================================

- low / nominal / high
- another documented FIRMS representation

The goal is reliable application data, not changing NASA's meaning.

============================================================
11. DUPLICATE DETECTION
============================================================

Implement duplicate detection.

The same hotspot record should not appear multiple times in the cleaned dataset.

First inspect the FIRMS data structure.

If the API provides a unique event/detection identifier, prefer using it.

If no reliable unique identifier is available, create a deterministic duplicate key using appropriate fields such as:

- latitude
- longitude
- date
- relevant detection attributes

Do NOT use only latitude and longitude as the duplicate key.

Why?

Because two legitimate hotspot detections can occur at the same location on different dates.

Therefore:

same coordinates + different date

should NOT automatically be treated as a duplicate.

Document the duplicate strategy in comments.
