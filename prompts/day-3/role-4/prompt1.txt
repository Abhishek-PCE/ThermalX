8. IMPLEMENT SPATIAL DISTANCE CALCULATION
==================================================

Use Turf.js for geographic calculations.

Do NOT manually implement the Haversine formula unless there is a specific reason.

Create a reusable function such as:

calculateDistanceKm(hotspotA, hotspotB)

It should:

1. Create Turf point features from longitude and latitude.
2. Calculate geographic distance using Turf.js.
3. Return distance in kilometers.

Remember:

GeoJSON/Turf coordinate order is:

[longitude, latitude]

NOT:

[latitude, longitude]

This is extremely important.

Add a code comment explaining this.

Example conceptual logic:

const pointA = turf.point([
    hotspotA.longitude,
    hotspotA.latitude
]);

const pointB = turf.point([
    hotspotB.longitude,
    hotspotB.latitude
]);

const distance = turf.distance(pointA, pointB, {
    units: "kilometers"
});

return distance;

Use the Turf.js version already present in the project.

Do not introduce another GIS library.

9. IMPLEMENT NEARBY DETECTION GROUPING
==================================================

This is the MAIN task.

Historical FIRMS detections may represent the same persistent thermal source across different days.

Example:

Day 1:
lat = 25.123
lon = 85.456

Day 2:
lat = 25.124
lon = 85.457

Day 3:
lat = 25.122
lon = 85.455

These should potentially belong to the same thermal event if they fall within a reasonable spatial radius.

Create a reusable function such as:

groupNearbyDetections(detections, radiusKm)

The function should:

1. Receive historical hotspot detections.
2. Compare their geographic positions.
3. Use Turf.js distance calculations.
4. Group detections that are spatially close.
5. Return structured groups.

Do NOT assume that identical latitude/longitude values are required.

Satellite detections can have small positional differences.

11. UNIQUE DAY DETECTION
==================================================

For each grouped event, calculate:

- detectionCount
- uniqueDays
- firstDetection
- lastDetection

A hotspot detected multiple times on the same date should not automatically count as multiple persistent days.

For example:

June 1 → 3 detections
June 2 → 2 detections
June 3 → 1 detection

The event should have:

detectionCount = 6

uniqueDays = 3

This distinction is important for persistence.

Use normalized date values when comparing days.

If timestamps exist, normalize them to calendar dates when calculating unique days.
